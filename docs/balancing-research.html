1Hub submission — not yet, and here's exactly why

Verdict: hold. Two hard blockers, one soft one — roughly one working session plus one soak-playtest away from ready.
  • Balancing (hard). Simulation with researched F2P earn rates: the current curve (250·(i+1)^1.35) totals ~2,150 hours with the last drafts costing 25 h each — an order of magnitude past the design target ("late draft every few hours").   • Soak test (hard). v0.2 shipped after checklist tests, not sustained play. Item locks, void XP, and the new curve need one 5–10 hour honest playthrough before strangers run it. The balancing build adds per-pick timestamps so that playthrough doubles as pacing telemetry.

Otherwise ready: repo public, README/icon/properties/checklist done (docs/hub-submission.md), plugin is restriction-only (removes capabilities, no automation) which is the category hub review reliably passes.

2Balancing — research and the chosen model

What the earn side actually looks like (researched, F2P)

PhaseSkilling pts/h (1pt/10xp)Kill pts/hCombined, realistic
Early (fresh account, starter regions)500–1,500300–1,000 (chickens→goblins)~1,000
Mid (~50s skills, several regions)3,000–6,0002,000–3,500 (guards/hill giants)~4,000
Late (70s+, most content)5,000–15,0003,500–5,000 (plateaus!)~8,000
  • Earn rate grows ~8–10× early→late — not the ~80× the current exponent silently assumes.
  • Kill points plateau at ~3–4k/h from combat level ~28 upward (kills/h falls as combat level rises). Fix candidate for v0.3: scale kill points by HP rather than combat level alone.
  • Exploit surface: GE-fed artisan skills (wine cooking ≈ 470k xp/h ⇒ 47k pts/h). Mitigation is the design doc's per-skill diminishing returns — scheduled v0.3; ironman-style players are unaffected.

Design-literature consensus: pick the wall-clock cadence first, then derive cost(i) = expected_rate(i) × target_interval(i); time-per-unlock growing ~5–20× start→end is the envelope that feels good in long games. Growth of 100×+ appears only in games where quitting-and-resetting is the intended response.

Recommendation: the paced curve. Cost is the product of two explicit, named models — the earn-rate model and the target draft interval:
R(i) = 1,000 + 7,000 · (i/142)^0.8   // expected points/hour at draft i (researched)
H(i) = 0.35 + 2.15 · (i/142)        // target hours between drafts: 21 min → 2.5 h (7×)
cost(i) = round25( R(i) · H(i) )     // 350 → 20,000 points
Why this over a tuned exponent: the four constants ARE the game-feel knobs (early rate, late rate, first interval, last interval) — after the soak playtest we adjust the constant that's wrong instead of re-deriving an opaque exponent. Totals: ~1.17M points ≈ 11.7M XP-equivalent (one 99-skill scale), ~200 hours to 100% — squarely in restriction-mode territory without Tileman's 2,500-hour extreme. Deterministic and seed-fair like today. Implementation ships with per-pick timestamps in the profile (pacing telemetry) so the soak test measures real intervals against H(i).

Migration: the curve is a stateless function of choiceIndex — no profile migration needed. In-flight runs simply see cheaper next thresholds (a one-time catch-up burst of drafts for accounts with banked points, e.g. the test account). Fresh runs are unaffected.
