v0.1 Plugin Skeleton Plan

Choice-unlock gamemode · RuneLite external plugin · approved scope: draft 1-of-3 + reroll · F2P regions + monsters only

1Scope lock (what v0.1 is and isn't)

In: point accrual from XP + kills · escalating thresholds · seeded 1-of-3 draft with 1 reroll per event · region locks (map-square granularity) + monster locks · starter kit · enforcement overlays + menu stripping · side panel · per-account JSON profile.

Out (deferred): item tags, skill locks, quests, curses, diminishing XP returns (flat rates v0.1), group mode, cloud sync, members content.

2Foundation

  • Scaffold from runelite/example-plugin template (Gradle, Java 11, RuneLite client dep from repo.runelite.net). Pull the latest template at scaffold time — it moves.
  • Plugin Hub metadata (runelite-plugin.properties + icon.png) included from day one so submission is a PR, not a refactor.
  • Working name: display name "Pathlocked", package com.pathlocked, config group pathlocked. Renaming later is cheap until Hub submission — after that the config group is frozen (it keys user settings).
  • Region granularity = map squares (64×64 tiles, WorldPoint.getRegionID()) — same as Region Locker. F2P surface is ~100–130 squares; big enough to feel meaningful, small enough to curate.

6Draft algorithm (deterministic core)

  1. Candidates = frontier only: regions adjacent to an unlocked region; monsters whose home region is unlocked (or arrives with the drafted region). This is the softlock guard.
  2. Weight by tier distance from the player's current band (adjacent tier favored, +1 stretch option possible).
  3. RNG = new Random(seed ^ choiceIndex ^ rerollCount) → offers are reproducible from the profile alone; reroll is deterministic too (seeded-run feature falls out for free).
  4. Category wheel: alternate region-event / monster-event; every 5th event = free pick from the frontier.
  5. Playability invariant after every unlock: ≥ 3 attackable monster types and ≥ 1 draftable frontier region remain, else inject a rescue option. Enforced in DraftService, unit-tested by simulating 500 full runs across random seeds.

Order rationale: 2 and 3–5 are parallelizable (data vs logic); 5 depends on 2's schema, not its full contents (test with a stub map early). Everything client-facing (6–7) lands after the logic core is unit-tested.

8Dev & test loop

  • PathlockedPluginTest#main launches a local RuneLite with the plugin injected (template-standard) — the daily dev loop.
  • Pure-logic packages get real unit tests (JUnit, no client mocks): curve values, draft determinism, softlock simulation, JSON validation.
  • Manual QA checklist lives in docs/: fresh account, relog persistence, locked-NPC menu, map shading, reroll determinism.

9Defaults I chose (veto if wrong)

  1. Working name Pathlocked (package/config-group); trivially renameable until Hub submission.
  2. Map-square (64×64) region granularity, not 8×8 chunks — matches Region Locker, 10× less curation.
  3. Flat point rates in v0.1 (TCG's proven numbers as the starting tune); diminishing returns deferred to v0.2.
  4. File-based profiles under ~/.runelite/pathlocked/, not ConfigManager blobs — structured data, easy manual rescue.
  5. Draft prompt as in-game overlay cards (not just side panel) — the choice moment is the product; it should interrupt.
Known unknown: exact template/API details (event names, panel APIs) drift between RuneLite releases — task 1 includes reconciling this plan against the current example-plugin and client javadocs before any code is written on top.
Definition of done for v0.1: a fresh F2P account can play a full session where every unlock they have came from a draft; state survives relog; a 500-seed simulation shows no softlocks; repo builds clean and is structurally ready for a Plugin Hub PR.
